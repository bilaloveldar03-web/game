# Бесплатное обновление футбольной базы

Публичный поток для [ФНЛ Менеджера](https://fnl-manager-41-play.bilaloveldar03.chatgpt.site).
Python 3, стандартная библиотека, GitHub Actions на обычном Linux runner. Платных API и подписок нет.

## Как работает

Ежедневно около **05:37 UTC** GitHub Actions читает восемь календарей сезона 2026/27 из
[openfootball/football.json](https://github.com/openfootball/football.json/tree/master/2026-27),
проверяет даты, клубы, пары матчей и счета, рассчитывает таблицы и публикует `data/live.json`.
Данные openfootball распространяются как CC0. Таблица рассчитана по результатам, без дисциплинарных
снятий очков и специальных правил равенства. Отсутствие счета не принимается за 0:0.

Время скачивания `checkedAt` отделено от даты последнего результата `dataAsOf`.
Если источник устарел, это видно в игре. При ошибке сохраняется последний корректный компонент.
При первой установке результаты источника заканчиваются сентябрём 2026: это **не актуальная таблица ноября**.

Игра проверяет поток при открытии и затем раз в шесть часов. Сохранённая карьера сохраняет свой
календарь и результаты. Стартовая база новой карьеры принимает только полные данные, покрывающие её
стартовую дату. Реальные таблицы и календарь доступны отдельно в центре базы.
Резервная локальная копия позволяет открыть игру без сети.

## Покрытие и ограничения

Подключены АПЛ, Чемпионшип, Бундеслига, Ла Лига, Серия А, Лига 1, Эредивизи и Португалия.
У бесплатного upstream нет гарантии оперативности. GitHub может задерживать расписание;
в публичном репозитории расписания могут отключаться после 60 дней без активности.
Для немедленной проверки: **Actions → Free football data sync → Run workflow**.

Для РПЛ, Первой и Второй лиг текущий бесплатный источник не подключён. Никакие старые сезоны
или модельные результаты не выдаются за реальные. API-Football требует отдельного аккаунта/ключа;
доступность текущего сезона на бесплатном плане нужно проверять. API в эту схему не включён.

## Рыночные стоимости

Прямой массовый доступ к Transfermarkt отсутствует. Автоматический скрейпер и обход ограничений
не используются. До появления актуального источника игровые цены остаются игровыми оценками.

Для одной разрешённой **массовой** выгрузки всех игроков поддержан файл
`data-sync/inbox/market.json`. Не требуется вводить клубы по одному. Формат:

```json
{"checkedAt":"2026-11-03","players":[{"transfermarktId":123,"name":"Exact game name","dateOfBirth":"2000-01-01","valueEUR":1000000,"valuationDate":"2026-10-01","sourceUrl":"https://www.transfermarkt.com/player/profil/spieler/123"}]}
```

Это пример формата, не реальная оценка. В репозитории нет тестовых цен. После появления такого
файла тот же бесплатный job проверит его целиком. В игре нужны совпадения имени, даты рождения и
установленного Transfermarkt ID; оценки старше 120 дней, дубликаты и неоднозначные личности
автоматически не применяются. Новая оценка применяется один раз; её дата не обновляется при скачивании.
Публичный репозиторий предназначен только для открытых данных. Не добавляйте ключи и секреты.

## Локальный запуск

```sh
python data-sync/collector.py
python -m unittest discover -s data-sync -p 'test_*.py'
```

Сборщик обращается только к `raw.githubusercontent.com`. Новые источники требуют отдельной
проверки доступности, прав на данные и сопоставления клубов. Пустые ответы и ошибочные календарные
файлы не заменяют последнюю рабочую базу. Job ограничен 12 минутами и не запускает сам себя.
